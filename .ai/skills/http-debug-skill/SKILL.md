# http-debug-skill

**Answer in Chinese（使用中文回答）**

debug skill

## 标准执行规范

### 目标

说明这个 skill 要解决的问题、输入材料和最终输出。

### 适用范围

#### 触发关键词

- 在这里列出应触发本 skill 的用户说法、日志 tag、模块名或业务关键词。

#### 排除关键词

- 在这里列出不应由本 skill 处理、应转交其他 skill 的场景。

### 工作边界

1. 只基于真实输入、工具调用、源码和日志证据输出结论。
2. 证据不足时明确写缺口，不编造日志、源码或根因。
3. 不把单个历史 case 的包名、PID、时间、字段写成通用规则。

### 输入要求

| 输入 | 必填 | 说明 |
|---|---:|---|
| 问题描述 | 是 | 用户现象、目标对象或排查诉求 |
| 日志路径 | 视情况 | 需要运行证据时必须提供 |
| 问题时间 | 推荐 | 用于锁定时间窗和减少噪声 |

### 主执行链路

1. 提取用户诉求、时间、日志和关键对象。
2. 根据本 skill 范围选择工具、脚本或源码读取路径。
3. 获取证据并区分结论、现象、缺口和推断。
4. 先输出结论，再列证据、待确认项和建议动作。

### 判断逻辑

- 日志证据和源码证据互相印证时，结论可信度最高。
- 只有单侧证据时，必须标注静态结论或日志现象。
- 未命中证据不等于问题不存在，需说明日志覆盖和检索范围。

### 工具/脚本调用规范

1. 优先使用本 skill 自带脚本或明确的工具调用。
2. 参数要区分日志路径、时间窗、tag、content、目标对象，不能混用。
3. 失败时报告失败阶段和可复跑命令。

### 证据规范

1. 关键判断必须能回指到源码路径、工具结果或日志文件行号。
2. 原始字段、时间、PID、tag 和枚举名不得改写。
3. 重复日志要合并摘要，但保留代表样本。

### 输出模板

```markdown
## 结论摘要
- 一句话说明最可能原因、影响范围和可信度。

## 关键证据
- 列出可回溯的日志、源码或工具证据。

## 最可能原因
- 按证据强弱排序说明原因。

## 待确认项
- 列出当前材料无法证明的点。

## 建议动作
- 给出下一步可执行动作。
```
